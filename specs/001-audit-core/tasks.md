- [ ] T024c [P] Deploy the **standalone sandbox tier** per [sandbox-runtime.md](./contracts/sandbox-runtime.md) + `deploy/sandbox/`: template registry (`tmpl-crawl`/`tmpl-convert`/`tmpl-coderun`) + **default-deny egress proxy** (crawl gets the `web_distill` SSRF allowlist, convert gets none); `SANDBOX_URL`/`SANDBOX_KIND` config; the **only** holder of the pool + keys. **The Phase-1 boundary is "hardened container, no microVM"; the kind is per-environment** — `SANDBOX_KIND=service` on the **first DO-droplet deploy** (docker-compose, no Kubernetes API — long-lived sandbox services that mount **no runtime socket at all**; `SANDBOX_RUNTIME=runsc` is the free gVisor upgrade there since the droplet is Linux), `SANDBOX_KIND=docker` on **local macOS dev only**, and `k8s_pod` on k3s/EKS (created through an RBAC-scoped ServiceAccount, **no container-runtime socket anywhere**). No new node group and no metal in either case. **Under `docker` (local macOS dev only), invariant 8 is an active obligation:** the socket goes to the sandbox executor alone, never to `go-api`/`go-relay`/`go-worker`/`py-api`/`py-worker`/`py-mcp`/`llm-gateway`/`crawl`. Hardening is mandatory and contract-tested: `runAsNonRoot`, `readOnlyRootFilesystem`, `capabilities: {drop: [ALL]}`, `seccompProfile: RuntimeDefault`, `automountServiceAccountToken: false`, `resources.limits` from the spec's `vcpu`/`mem_mb`, a **PID cap** (`podPidsLimit` on the sandbox node pool — node-level kubelet config, not a pod field; `--pids-limit` under `SANDBOX_KIND=docker`), plus a `NetworkPolicy` default-deny egress. Cold-start relief is bought **in order, cheapest-and-safest first**: (1) **pre-pull** template images onto sandbox nodes (DaemonSet warmer, or pinned `@sha256` + `IfNotPresent`) — the biggest win, since an uncached pull turns ~2 s into 30 s+; (2) **scheduling headroom** via a negative-priority `PriorityClass` placeholder pod that a real sandbox preempts instantly — no freshness state to track; (3) **measure** (1–2 s is typically enough against a crawl path already spending seconds on fetch + distill); (4) **only then** a pooled claim, and only for `tmpl-crawl`/`tmpl-convert`. If a pool is built it is a lease protocol with four obligations — atomic claim, claimed-never-returns, **failure paths destroy rather than return**, and provably-pristine members — all contract-tested (T026a), because each fails silently and degrades `max_runs=1` into `max_runs=N`. `tmpl-coderun` is **never pooled**. Plus `max_runs_per_sandbox` and a mandatory workspace-boundary recycle. The KVM/`*.metal` node group (`deploy/eks/terraform/sandbox.tf`, `sandbox_enabled` **default false**) stays unprovisioned until Phase 2 (research §24)
